Why Addressing Modes Matter

In high-level languages, you write arr[i] = arr[i] + 1 and the compiler handles all memory access transparently. In assembly, you are the one who decides exactly how the CPU reaches each byte of memory. Mastering addressing modes gives you:

  • 🔬 Complete control over memory layout and access patterns
  • ⚡ Performance optimization – choosing the right mode can reduce instruction count
  • 🛡️ Vulnerability analysis – buffer overflows exploit pointer arithmetic mistakes
  • 🔍 Reverse engineering – recognizing addressing patterns reveals data structures
💡 Core concept: An addressing mode answers one question: "Where does the CPU find the data for this instruction?" It could be inside the instruction itself, inside a register, or somewhere in memory – and "somewhere in memory" has many ways to be specified.

The MOV Family: MOV, MOVZX, MOVSX, XCHG

🔹 MOV – The Fundamental Data Mover

MOV copies data from a source to a destination. It does not remove data from the source – think "copy," not "cut."

MOV  eax, 42          ; immediate → register (EAX = 42)
MOV  ebx, eax          ; register → register (EBX = 42)
MOV  ecx, myVar        ; memory → register (ECX = value at myVar)
MOV  myVar, edx        ; register → memory (store EDX into myVar)
⚠️ Restriction: Both operands must be the same size. You cannot MOV ax, ebx (16-bit vs 32-bit). Also, memory-to-memory MOV is not allowed in x86 – you must use a register as an intermediary.

🔹 MOVZX – Move with Zero-Extend

Copies a smaller source into a larger destination, filling the upper bits with zeros. Perfect for unsigned values.

MOV  al, 0xFF          ; AL = 255 (unsigned)
MOVZX ebx, al          ; EBX = 0x000000FF (255, zero-extended)
AL (8-bit): 11111111 ↓ MOVZX EBX (32-bit): 00000000 00000000 00000000 11111111 (upper 24 bits = zero)

🔹 MOVSX – Move with Sign-Extend

Copies a smaller source into a larger destination, preserving the sign by replicating the most significant bit. Essential for signed values.

MOV  al, 0xFF          ; AL = -1 (signed interpretation)
MOVSX ebx, al          ; EBX = 0xFFFFFFFF (-1, sign-extended)
AL (8-bit): 11111111 (MSB=1, so negative) ↓ MOVSX EBX (32-bit): 11111111 11111111 11111111 11111111 (upper 24 bits = sign bit copy)

🔹 XCHG – Exchange Two Operands

Swaps the contents of two registers, or a register and a memory location. No temporary storage needed! 

MOV  eax, 10
MOV  ebx, 20
XCHG eax, ebx          ; now EAX=20, EBX=10 – swapped!

LEA – Load Effective Address

LEA computes a memory address and stores that address (not the data at that address) into a register. It's an address calculator – no memory is read.

🔹 LEA vs MOV with OFFSET

; Assume myArray is at memory address 0x00403000

MOV  esi, OFFSET myArray   ; ESI = 0x00403000 (address computed at assemble time)
LEA  esi, myArray          ; ESI = 0x00403000 (same result for simple label)

; But LEA can do arithmetic that OFFSET cannot:
LEA  esi, [ebx + ecx*4 + 8]  ; ESI = EBX + (ECX × 4) + 8
                              ; This is computed at RUNTIME – far more flexible!
💡 Key insight: LEA is often used for fast arithmetic (e.g., LEA eax, [eax + eax*4] multiplies EAX by 5 in one instruction, without touching memory). It's also essential for obtaining the address of stack variables and array elements.

🔹 Practical LEA Use Cases

; 1. Get address of a local variable on the stack
LEA  eax, [ebp - 4]        ; EAX = address of local DWORD variable

; 2. Compute array element address without reading memory
LEA  edx, [esi + edi]      ; EDX = ESI + EDI (pointer arithmetic)

; 3. Fast multiply by constant
LEA  ecx, [eax + eax*2]    ; ECX = EAX * 3 (no MUL needed!)
LEA  ecx, [eax + eax*4]    ; ECX = EAX * 5
LEA  ecx, [eax + eax*8]    ; ECX = EAX * 9

The Three Operand Types

Every x86 instruction works with operands. Understanding the three fundamental types is the foundation of addressing modes.

① Immediate
The value is inside the instruction itself.
MOV eax, 100
ADD ebx, 0x1A
Fast – no memory access needed. The constant is embedded in the opcode bytes.
② Register
The value is inside a CPU register.
MOV eax, ebx
ADD ecx, edx
Fastest – no memory bus traffic. Operands are inside the CPU core.
③ Memory
The value is in RAM, referenced by an address.
MOV eax, [esi]
ADD ebx, [myVar]
Slower – requires address calculation and memory bus access. But essential for large data.
📌 Important: In MASM, writing MOV eax, myVar (without brackets) and MOV eax, [myVar] (with brackets) both load the value from memory for named variables. However, for register-indirect addressing, brackets are required: MOV eax, [esi] loads the value at address ESI, while MOV eax, esi loads ESI itself. Be explicit with brackets to avoid confusion.

All x86 Addressing Modes (32-bit)

The x86 architecture supports a remarkably flexible set of memory addressing modes. Here's the complete reference:

Mode MASM Syntax Effective Address Example Use
Immediate imm N/A (value is in instruction) MOV eax, 100
Register reg N/A (value is in register) MOV eax, ebx
Direct [label] Address of label (fixed) MOV eax, [myVar]
Register Indirect [reg] Value in register MOV eax, [esi]
Based [reg + disp] reg + displacement MOV eax, [ebx + 8]
Indexed [reg + reg*scale] reg + (index × scale) MOV eax, [esi + edi*4]
Based-Indexed [base + index*scale] base + (index × scale) MOV eax, [ebx + esi*4]
Based-Indexed w/ Disp [base + index*scale + disp] base + (index × scale) + displacement MOV eax, [ebx + esi*4 + 16]

* Valid base registers: EAX, EBX, ECX, EDX, ESI, EDI, EBP, ESP (any 32-bit general-purpose register). Valid index registers: EAX, EBX, ECX, EDX, ESI, EDI, EBP (all except ESP). Valid scale factors: 1, 2, 4, 8.

🔹 Indirect Addressing – The Gateway to Dynamic Memory

MOV  esi, OFFSET myArray     ; ESI = address of myArray
MOV  eax, [esi]              ; EAX = first DWORD at that address (indirect)
ADD  esi, 4                  ; move pointer to next DWORD
MOV  ebx, [esi]              ; EBX = second DWORD
ESI ──────► [0x00403000] → 12 (myArray[0]) ESI+4 ────► [0x00403004] → 7 (myArray[1]) ESI+8 ────► [0x00403008] → 25 (myArray[2])

🔹 Indexed Addressing with Scale Factor

The scale factor (1, 2, 4, or 8) automatically multiplies the index register – perfect for array element sizes:

; Array of DWORDs (4 bytes each)
; Access myArray[i] where ECX = i
MOV  eax, [myArray + ecx*4]    ; scale=4 because DWORD = 4 bytes

; Array of WORDs (2 bytes each)
MOV  ax, [myArray + ecx*2]     ; scale=2 because WORD = 2 bytes

🔹 Base-Index Addressing with Displacement

The most general form combines everything. Think of it as: address = base_register + index_register × scale + constant_offset

; Access struct member: assume EBX = struct base, ESI = array index
MOV  eax, [ebx + esi*4 + 12]   ; offset 12 bytes into struct, element ESI

; Equivalent C:  eax = struct_ptr->data_array[i];  // where data_array offset = 12

Data Definition Directives: DB, DW, DD, DUP

Before you can address data, you must define it. MASM provides directives to allocate and initialize memory in the .data section.

Directive Size C Equivalent Example
DB 1 byte char, unsigned char myByte DB 0x41
DW 2 bytes short, unsigned short myWord DW 1000
DD 4 bytes int, float, pointer myDword DD 12345678h
DQ 8 bytes long long, double myQword DQ 0
DUP (repeats) Array declaration buffer DB 256 DUP(0)

🔹 Common Data Definition Patterns

.data
    ; Single values
    count      DD  0                ; 32-bit integer, initialized to 0
    pi         DD  3.14159          ; 32-bit float (use REAL4 for clarity)
    flag       DB  1                ; byte-sized boolean flag
    letter     DB  'A'              ; ASCII character (0x41)
    greeting   DB  'Hello', 0       ; null-terminated string

    ; Arrays
    scores     DD  85, 92, 78, 95, 88         ; array of 5 DWORDs
    hexBytes   DB  0Ah, 0Bh, 0Ch, 0Dh, 0Eh    ; array of bytes

    ; Using DUP for large buffers
    buffer     DB  1024 DUP(0)      ; 1024 bytes, all zero
    matrix     DD  16 DUP(?)        ; 16 DWORDs, uninitialized
    pattern    DB  10 DUP('X')      ; 10 copies of 'X'

    ; Mixed types
    studentId  DD  2024001
    studentName DB 'Mahmoud Khalil', 0
    studentGPA  DD  3.75
📌 Memory layout note: Data is laid out sequentially in the order you declare it. The assembler assigns increasing addresses. Multi-byte values (DW, DD, DQ) are stored in little-endian byte order (least significant byte at the lowest address).

Working with Arrays – Traversal Techniques

Arrays are contiguous blocks of memory. In assembly, you traverse them by updating a pointer register (ESI, EDI, EBX) or by using an index register with a scale factor.

🔹 Method 1: Pointer Walking (Register Indirect)

; Sum all elements of a DWORD array
.data
    arr   DD  10, 20, 30, 40, 50
    arrSize = ($ - arr) / 4      ; calculate number of elements
    total DD  ?

.code
    mov  esi, OFFSET arr         ; ESI points to first element
    mov  ecx, arrSize            ; loop counter
    xor  eax, eax                ; sum accumulator = 0

sum_loop:
    add  eax, [esi]              ; add current element to sum
    add  esi, 4                  ; move pointer to next DWORD (4 bytes)
    loop sum_loop

    mov  total, eax              ; store final sum

🔹 Method 2: Index Register with Scale

; Same task, using index + scale
    xor  eax, eax                ; sum = 0
    xor  ecx, ecx                ; index i = 0

sum_loop2:
    cmp  ecx, arrSize
    jge  done
    add  eax, [arr + ecx*4]      ; arr[i] – scale=4 for DWORD
    inc  ecx
    jmp  sum_loop2
done:
    mov  total, eax

🔹 Method 3: Base-Index with Two Registers

; Using EBX as base, ESI as index
    mov  ebx, OFFSET arr         ; base address
    xor  esi, esi                ; index = 0
    xor  eax, eax

sum_loop3:
    cmp  esi, arrSize
    jge  done3
    add  eax, [ebx + esi*4]      ; base + index*scale
    inc  esi
    jmp  sum_loop3
done3:

Pointer vs. Value – The Critical Distinction

This is one of the most important concepts in assembly (and in C). A pointer is an address – a number that tells you where something is. A value is the actual data at that address.

Register ESI: 0x00403000 ← This is a POINTER (address) Memory at 0x00403000: 42 ← This is a VALUE (data)

🔹 The Square Bracket Rule

MOV  eax, esi        ; EAX = ESI (copies the POINTER/address itself)
MOV  eax, [esi]      ; EAX = value AT address ESI (dereferences the pointer)

; Think of it as C:
; eax = esi;    →  eax = (int)esi;        (treat ESI as a number)
; eax = [esi];  →  eax = *(int*)esi;      (load value from that address)

🔹 Common Confusion – Watch Out!

.data
    myVar  DD  99

.code
    MOV  eax, myVar        ; EAX = 99 (the VALUE at myVar)
    MOV  eax, OFFSET myVar ; EAX = address of myVar (a POINTER)
    LEA  eax, myVar        ; EAX = address of myVar (same result as OFFSET)

    ; Now with indirect:
    MOV  esi, OFFSET myVar ; ESI = pointer to myVar
    MOV  eax, esi          ; EAX = the address (not 99!)
    MOV  eax, [esi]        ; EAX = 99 (dereferenced – got the value)
⚠️ Debugging tip: If your register contains a strange large number like 0x00403000 when you expected a small value like 99, you probably forgot the brackets and loaded the pointer instead of the value. This is the #1 beginner mistake!

Complete Example: Copy an Array Using ESI & EDI

ESI is traditionally the source index and EDI the destination index. This convention comes from the string instructions, but it's widely used for all memory operations.

; Copy contents of source array into destination array
.386
.model flat, stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
    source    DD  10, 20, 30, 40, 50
    srcSize   =   ($ - source) / 4
    dest      DD  5 DUP(0)           ; allocate space for 5 DWORDs

.code
main PROC
    mov  esi, OFFSET source          ; ESI = source pointer
    mov  edi, OFFSET dest            ; EDI = destination pointer
    mov  ecx, srcSize                ; ECX = number of elements

copy_loop:
    mov  eax, [esi]                  ; load from source
    mov  [edi], eax                  ; store to destination
    add  esi, 4                      ; advance source pointer (DWORD = 4 bytes)
    add  edi, 4                      ; advance destination pointer
    loop copy_loop

    ; Verify: dest now contains {10, 20, 30, 40, 50}

    INVOKE ExitProcess, 0
main ENDP
END main
🔍 Trace in debugger: Set breakpoints at copy_loop. Watch ESI and EDI increment by 4 each iteration. Examine the memory at dest – it fills up one DWORD per loop pass.

Lab Exercise – Reverse an Array In Place

Objective: Reverse the elements of a DWORD array in place using only registers and indirect addressing. No additional arrays allowed – you must swap elements within the same memory block.

🔹 The Algorithm

  1. Set one pointer (ESI) to the first element (left side).
  2. Set another pointer (EDI) to the last element (right side).
  3. Swap the values at ESI and EDI using a temporary register.
  4. Move ESI forward by 4 bytes, EDI backward by 4 bytes.
  5. Repeat until ESI ≥ EDI (pointers meet or cross in the middle).
Before: [10] [20] [30] [40] [50] ↑ESI ↑EDI Swap 1: [50] [20] [30] [40] [10] ↑ESI ↑EDI Swap 2: [50] [40] [30] [20] [10] ↑ESI,EDI (meet → done!) After: [50] [40] [30] [20] [10] ✓ Reversed!

📋 Complete Reverse Array Program

; reverse_array.asm – Reverse a DWORD array in place
.386
.model flat, stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
    arr     DD  10, 20, 30, 40, 50
    arrSize =   ($ - arr) / 4        ; number of elements

.code
main PROC
    ; Set up left and right pointers
    mov  esi, OFFSET arr             ; ESI = &arr[0] (left pointer)
    mov  edi, OFFSET arr             ; EDI = &arr[0]
    mov  eax, arrSize
    dec  eax                         ; EAX = last index
    ; EDI = &arr[last_index]
    lea  edi, [edi + eax*4]          ; EDI = address of last element

reverse_loop:
    cmp  esi, edi                    ; have pointers crossed?
    jge  done                        ; if ESI >= EDI, we're finished

    ; Swap [ESI] and [EDI] using EAX and EBX as temporaries
    mov  eax, [esi]                  ; EAX = value at left pointer
    mov  ebx, [edi]                  ; EBX = value at right pointer
    mov  [esi], ebx                  ; left gets right's value
    mov  [edi], eax                  ; right gets left's value

    ; Move pointers toward the middle
    add  esi, 4                      ; left moves right (next DWORD)
    sub  edi, 4                      ; right moves left (previous DWORD)
    jmp  reverse_loop

done:
    ; Array is now reversed: {50, 40, 30, 20, 10}
    INVOKE ExitProcess, 0
main ENDP
END main

🔎 Step-by-Step Debugger Trace Guide

  1. Assemble and link: ml /c /coff reverse_array.asm → link /SUBSYSTEM:CONSOLE reverse_array.obj kernel32.lib
  2. Open x64dbg and load reverse_array.exe.
  3. Set a breakpoint at the first instruction after main PROC.
  4. Step through (F7) and watch:
    • ESI starts at the array base address.
    • EDI is computed as base + (size-1)×4.
    • In each swap iteration, the memory dump at arr updates.
    • After the loop, examine memory – the array is reversed!
  5. Take screenshots of: (a) registers after pointer setup, (b) memory before first swap, (c) memory after each swap, (d) final reversed array.

Additional Practice Exercises

  1. Array Sum with Indirect: Write a program that sums all elements of a WORD array (2-byte elements) using register-indirect addressing. Watch your pointer increment size!
  2. Find Minimum: Using indexed addressing, find the smallest value in a DWORD array. Store the minimum value and its index.
  3. Count Occurrences: Given a byte array and a target byte value, count how many times the target appears. Use [esi] with byte-sized operations.
  4. LEA Arithmetic: Without using MUL or IMUL, compute y = x * 7 using only LEA and ADD. (Hint: 7 = 4 + 2 + 1, or use LEA to compute x*8 then subtract x.)
  5. Struct Field Access: Define a "student" structure in the data section with fields: ID (DWORD), grade (BYTE), and score (DWORD). Access each field using base+displacement addressing.
  6. Reverse a String: Apply the same in-place reversal technique to a null-terminated byte string. Watch out – bytes are 1 byte each, not 4!
