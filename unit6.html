📘 Unit 6 — Strings, Input/Output, and OS Interface

📌 Introduction

Assembly programs interact directly with memory, users, files, and the operating system. This unit focuses on strings, I/O, files, Windows API, and building interactive programs.

Key idea: Everything in assembly is handled manually — including strings, input, and system calls.

🧠 Strings in Memory

Strings are sequences of bytes ending with a null terminator (0).

msg DB "Hello",0

⚙️ String Registers

  • ESI → source pointer
  • EDI → destination pointer
  • ECX → counter
  • AL → current byte

📦 String Instructions

MOVSB → copy byte LODSB → load into AL STOSB → store AL CMPSB → compare bytes REP MOVSB → repeat operations

➡️ String Traversal

MOV ESI, OFFSET msg LODSB LOOP NextChar

🧰 Irvine32 Library

Provides simplified functions for input, output, file handling, and system interaction.

🖥️ Console Input/Output

  • WriteString → display text
  • WriteInt → display numbers
  • ReadString → input text
  • ReadInt → input numbers

📁 File Operations

Programs can create, read, write, and close files using system procedures.

🪟 Windows API

  • MessageBoxA → dialog box
  • ExitProcess → terminate program
  • stdcall → calling convention
INVOKE MessageBoxA, NULL, ADDR msg, ADDR title, MB_OK

🔐 XOR Encryption

Encrypted = Data XOR Key Data = Encrypted XOR Key

XOR is reversible and widely used in simple encryption systems.

📋 Menu Systems

Programs use loops and CMP/JMP to handle user menus.

CMP AL, '1' JE Encrypt

💻 Mini Project

Build a menu-driven XOR encryption system that:
  • Reads user input
  • Encrypts/decrypts text
  • Loops until exit
