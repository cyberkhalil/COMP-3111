Why C → Assembly? See the Real Machine

High‑level languages hide the processor. As a cybersecurity engineer, reading assembly lets you reverse compiler output, find exploits, and understand exactly what the CPU executes. This unit bridges C code and x86 assembly so you can think like both a developer and a debugger.

💡 Key insight: Every if, while, and for becomes a CMP + conditional jump (JE, JG). Every function call becomes CALL/RET with stack adjustments.

Example: C addition → Assembly

// C code
int a = 5, b = 10, c = 3;
int sum = a + b + c;

Under the hood (x86 assembly, MASM syntax):

mov eax, a         ; load value of 'a' into EAX register
add eax, b         ; EAX = 5 + 10 = 15
add eax, c         ; EAX = 15 + 3 = 18
mov sum, eax       ; store the final result back into memory

No magic — just registers and arithmetic. The compiler does exactly this.

Setting Up MASM + Visual Studio Code

  1. Install Visual Studio Build Tools (or Visual Studio Community) – includes ml.exe (MASM assembler) and link.exe.
  2. Windows SDK (required for Win32 API core libraries like kernel32 and user32).
  3. VS Code + extensions: MASM/TASM or x86 Assembly syntax highlight.
  4. Configure environment: Open “Developer Command Prompt for VS” or add MASM path to system variables.
  5. Test with a minimal .asm file: assemble with ml /c /coff example.asm then link link /SUBSYSTEM:CONSOLE example.obj.
📌 Pro tip: Use the “x86 Native Tools Command Prompt” to run ml/link without path headaches. All examples in this unit assume 32‑bit flat memory model.

First Assembly: "Hello, World!" (No External Libraries)

As required by the syllabus, we start with a classic "Hello, World!" using only the Windows API — no Irvine32, no C runtime. This gives you pure insight into system calls.

; hello_win32.asm
; Compile: ml /c /coff hello_win32.asm
; Link with Windows API Import Libraries: 
; link /SUBSYSTEM:WINDOWS hello_win32.obj user32.lib kernel32.lib

.386
.model flat, stdcall
option casemap:none

; === Windows API prototypes ===
MessageBoxA PROTO :DWORD, :DWORD, :DWORD, :DWORD
ExitProcess PROTO :DWORD

.data
    msg db 'Hello, World! This is your first MASM program.', 0
    title db 'COMP‑3111 Unit 2', 0

.code
main PROC
    ; Arguments are pushed from right to left (stdcall convention)
    push 0               ; MB_OK (OK button only)
    push offset title    ; Pointer to dialog title
    push offset msg      ; Pointer to message text
    push 0               ; hWnd = NULL (No parent window)
    call MessageBoxA

    push 0               ; exit code (0 = success)
    call ExitProcess
main ENDP
END main

Assemble & link:

ml /c /coff hello_win32.asm
link /SUBSYSTEM:WINDOWS hello_win32.obj user32.lib kernel32.lib

Run hello_win32.exe — a message box appears! 🎉 This is a true standalone executable.

🔍 Why this matters: No libraries, no black boxes. The CPU directly calls into system DLLs. Reverse engineers see exactly this pattern.

MASM Directives Explained (Your New Vocabulary)

Unlike simple emulators, MASM uses directives to tell the assembler how to structure and build the standalone executable. Let's break down what we just saw:

DirectiveMeaning
.386Allow 80386 instructions (enables 32-bit registers like EAX, EBX).
.model flat, stdcallFlat memory model (single 4GB address space) + stdcall calling convention (callee cleans stack).
.stack 4096Reserve 4KB for the runtime stack (return addresses, local variables).
.dataSection for initialized global variables.
.codeSection for executable CPU instructions.
PROTOFunction prototype (declares an external function from Windows API).
INVOKEAn advanced directive to call functions with argument checking (automatically handles pushes).
ENDEnd of source code, specifies the program entry point (e.g., END main).
💡 Syntax Note: MASM is case‑insensitive, but modern practice uses lowercase for directives/instructions and mixed case for labels/variables. Also, note that mov eax, a and mov eax, [a] do the exact same thing for explicit variables in MASM!

Add Three Integers – Data Section in Action

Now that you know the structural directives, let's look at a pure computational routine. This program uses .data for declaring integer variables, .code for mathematical instructions, and safely exits using the INVOKE wrapper directive.

; add_three.asm
.386
.model flat, stdcall
.stack 4096
ExitProcess PROTO, dwExitCode:DWORD

.data
    a       DWORD 5
    b       DWORD 10
    c       DWORD 3
    sum     DWORD ?

.code
main PROC
    mov eax, a            ; load first number (5) into EAX
    add eax, b            ; add second number (5 + 10 = 15)
    add eax, c            ; add third number (15 + 3 = 18)
    mov sum, eax          ; store final result (18) into 'sum' variable

    ; exit process cleanly using INVOKE directive
    INVOKE ExitProcess, 0
main ENDP
END main

What's happening? DWORD = Double Word (32-bit unsigned integer). The three values are allocated sequentially in memory. The CPU accumulates them inside the EAX register, then copies the total back to sum.

Assemble & link:

ml /c /coff add_three.asm
link /SUBSYSTEM:CONSOLE add_three.obj kernel32.lib

Run add_three.exe – it does nothing visible on the screen, but the result 18 (0x12) is securely updated in memory. We’ll verify it live with a debugger!

Core Instructions: MOV, ADD, SUB, INC, DEC

MOV dest, src
Copies data (register ← register, immediate → register, memory ↔ register).
mov eax, var , mov var, ebx
ADD dest, src
dest = dest + src, updates OF/SF/ZF/CF flags.
SUB dest, src
dest = dest – src, affects flags based on comparison.
INC dest
dest++ (increment by 1; faster execution than ADD 1).
DEC dest
dest-- (decrement by 1; common for loops counter).

🔍 Example: Subtracting & flags

mov eax, 10
sub eax, 10      ; ZF = 1 (Zero flag set because result is 0)
mov ebx, -1
cmp ebx, 0       ; SF = 1 (Sign flag set because result is negative)
💡 The EFLAGS register shifts instantly after arithmetic: Zero flag (ZF), Sign flag (SF), Carry flag (CF - unsigned overflow), and Overflow flag (OF - signed overflow).

Translating C Control Flow to Assembly

Compilers convert structured high-level logic into comparison instructions and conditional jumps. Mastering this pattern is the key to mastering disassembly analysis.

If-Else Example

// C
if (x > y) max = x;
else max = y;

Assembly translation (x in EAX, y in EBX):

    cmp eax, ebx
    jle else_label   ; jump if EAX <= EBX
    mov max, eax
    jmp done
else_label:
    mov max, ebx
done:

While Loop

// C
while (count > 0) {
    sum += count;
    count--;
}
    mov ecx, count
    xor eax, eax    ; sum = 0
while_start:
    cmp ecx, 0
    jle while_end
    add eax, ecx
    dec ecx
    jmp while_start
while_end:
    mov sum, eax

Every high-level loop is just a CMP, conditional jump, and an unconditional JMP back.

Assemble, Link & Trace with a Debugger

Lab requirement: “Write a program that adds three integers and stores the result – then trace it in a debugger”. Let’s see how to witness every CPU step.

  1. Assemble and link add_three.asm → add_three.exe.
  2. Launch x64dbg (or OllyDbg / VS debugger).
  3. Load the executable, set a breakpoint at main (or at the first instruction).
  4. Step through (F7 or F8) and watch EAX register change: after first MOV EAX becomes 5, after first ADD becomes 15, after second ADD becomes 18.
  5. Examine memory at address of sum – after final MOV you’ll see value 0x12 (18 decimal).
🔬 Debugger insight: You can also view the flags (ZF, CF, OF) in the registers panel. Try adding 0x7FFFFFFF + 1 to see overflow! 
; alternative code to observe overflow
mov eax, 0x7FFFFFFF
add eax, 1        ; now OF=1, EAX becomes 0x80000000 (negative)

Memory Layout for MASM Programs

When you write .data and .code, the assembler organizes sections into virtual pages:

  • .data – initialized global variables (Read/Write memory).
  • .data? – uninitialized data (faster loading, implicitly initialized to 0).
  • .const – read-only constants (Read-Only memory).
  • .code – executable instructions (Read/Execute memory).

The linker creates a flat 32‑bit virtual address space. Local variables will be stored on the runtime stack (Unit 5). For now, remember that MOV eax, var loads from memory, while MOV eax, OFFSET var loads the raw address of var.

mov esi, OFFSET array   ; ESI points to the base memory address of array
mov eax, [esi]           ; fetches the first element from ESI location
