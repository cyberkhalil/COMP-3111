Unit 7: Reverse Engineering & Dynamic Analysis

Introduction

Reverse engineering is the process of analyzing compiled software without source code to understand its internal behavior.

It focuses on machine instructions, memory, registers, and runtime execution behavior.

Used in:

  • Malware analysis
  • Security auditing
  • Digital forensics
  • Vulnerability research
  • Software debugging

Core Concept

  • Understanding compiled binaries
  • Analyzing execution flow
  • Inspecting memory and registers

Works directly on assembly instructions and executable memory.

x64dbg Tool

x64dbg is a Windows debugger used for dynamic analysis.

  • Disassembler
  • Memory viewer
  • Breakpoint manager
  • Stack analyzer
CPU View shows current instructions and execution flow in real time.

Debugging

  • Step Into → execute instruction by instruction
  • Step Over → skip function calls
  • Run → continue execution
  • Pause → stop execution

Compiler Patterns

Common assembly patterns generated by compilers:

CMP EAX, EBX JE EqualLabel

Loops:

MOV ECX, 5 LoopStart: DEC ECX JNZ LoopStart

Stack Analysis

  • Return addresses
  • Function parameters
  • Local variables
  • Recursive calls

Binary Patching

Patching modifies program behavior by editing instructions.

JZ Success → JMP Success
Example opcodes: NOP (90), RET (C3), JMP (E9)

Ethics

  • Legal and ethical usage only
  • Security research
  • Malware analysis
  • Educational purposes
Reverse engineering must never be used for piracy or unauthorized access.
