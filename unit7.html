💡 Dynamic analysis vs static disassembly: Dynamic lets you see the program’s live state (registers, memory, flags). Static is like reading a map; dynamic is like driving the car.

Navigating the x64dbg Interface

x64dbg is a powerful open‑source debugger for Windows (32/64‑bit). When you load an executable, you’ll see four main panes:

  • CPU view (Disassembly) – addresses, opcodes, assembly instructions, comments. The EIP/RIP arrow shows the next instruction to execute.
  • Hex dump – raw memory bytes. Perfect for inspecting hidden strings or encrypted data.
  • Memory map – lists sections (.text, .data, stack, heap, loaded DLLs). Helps identify writable vs executable regions.
  • Registers window – general purpose registers (EAX/RAX, EBX, ECX, EFLAGS). Flags like ZF (zero flag) control conditional jumps.

✨ Pro tip: Drag any .exe into x64dbg, press F9 to run, then use F7/F8 and watch the registers change.

Breakpoints – Taking Control

🔹 Software Breakpoint (INT3)

Press F2 on any instruction. The debugger replaces the first byte with 0xCC. When the program hits it, execution stops. Easy to use Modifies code

🔹 Hardware Breakpoint

Uses CPU debug registers (DR0–DR3). No code modification → harder to detect. Set via Breakpoints → Hardware breakpoint (execution, read, write).

Stepping commands

  • F7 – Step Into (enter function calls)
  • F8 – Step Over (execute function without entering)
  • F9 – Run (continue until next breakpoint or program exit)

Recognising C Patterns in Assembly

🧩 if‑else

; C: if (a > b) { a++; } else { b--; }
mov eax, [a]
cmp eax, [b]
jle else_part
inc a
jmp end_if
else_part:
dec b
end_if:

🔄 Loops (while/for)

loop_start:
cmp i, 10
jge loop_end
add sum, i
inc i
jmp loop_start
loop_end:

📞 Function calls (cdecl, 32‑bit)

push arg2
push arg1
call myFunction   ; result in EAX
; inside function prologue:
push ebp
mov ebp, esp
sub esp, 8        ; local variables

64‑bit calling convention (Windows): first 4 args in RCX, RDX, R8, R9, rest on stack. Return value → RAX.

🧠 Analyze arguments & return values: Before a call, inspect the stack window or registers. After the call, EAX/RAX holds the return value.

Basic Patching – Change JZ to JMP

Imagine a password check that jumps to “grant access” only if a condition is true. By changing a conditional jump to an unconditional JMP, we force the program to always take the success path.

; Original conditional check
cmp eax, 0x1234
jz  access_granted   ; only if equal
call wrong_password
access_granted:

🛠️ How to patch in x64dbg:

  1. Navigate to the conditional jump (jz/jnz/je).
  2. Press Space to assemble a new instruction.
  3. Type jmp access_granted (or the target address / label).
  4. Press Enter – the instruction turns red (modified).
  5. Right‑click in CPU view → Patches → Patch file → Save to executable file.
  6. Run the patched .exe – behavior is permanently altered.
⚠️ Keep an original backup. Patching should only be used for learning or authorised security testing.

Legal & Ethical Boundaries

✅ Permitted (with authorisation or for defense)

  • Analyzing malware to build signatures / improve protection.
  • Security testing of your own software (or with written consent).
  • Learning using crackmes or dedicated training binaries.
  • Interoperability research under specific legal exceptions.

🚫 Strictly forbidden

  • Bypassing license checks of commercial software for redistribution.
  • Reverse engineering to steal intellectual property.
  • Altering online game clients or cheating on servers you don't own.

Golden rule: Use these skills to understand & protect – never to attack or crack without permission.

Challenge: crackme.exe – Guided Investigation

Goal: You are given crackme.exe that asks for a password. Without knowing the real password, patch the executable so that it accepts any input.

⚠️ We will not give you the final instructions. Instead, follow this methodology to discover the patch yourself.

🔍 Step‑by‑step guide (no spoilers)

  1. Run the crackme normally – try random passwords like “test”, “1234”. Observe the failure message (“Wrong password” or similar).
  2. Load into x64dbg – drag crackme.exe into the debugger. Press F9 once to reach the entry point.
  3. Search for string references – Search → Current Module → String references. Look for the failure message. Double‑click to jump to the code that prints it.
  4. Identify the conditional jump – scroll up a little. You will likely see a CMP or TEST followed by a conditional jump (JZ, JNZ, JE, JNE). Set a breakpoint (F2) on that jump.
  5. Experiment – Run the program (F9), enter any password, and break at your breakpoint. Step with F8 and see whether it goes to the failure block or the success block.
  6. Modify the jump – while still in the debugger, press Space on the conditional jump. Change it to an unconditional JMP that points to the success address, or flip the condition (e.g., JZ → JNZ). Continue execution (F9). Does the program now accept your dummy password?
  7. Test with different inputs – restart (Ctrl+F2), run again, type a completely different random string. If it always succeeds, you found the correct patch.
  8. Make the patch permanent – Right‑click in CPU → Patches → Patch file → Save to executable file → save as crackme_patched.exe.

🏆 After you succeed

Write down the exact assembly change you made. You will have mastered the heart of dynamic patching. Submit the patched executable and a short report describing the original check and your modification.

This exercise is for education only – do not apply such techniques on real commercial software without permission.
